# رسائل البنك عبر اختصار iPhone

اختصار على iPhone يرسل رسالة العملية البنكية إلى `POST /bank-sms`. الخادم يقرأ منها المبلغ والعملة والمتجر وآخر 4 أرقام، ويحفظها في `bank_transactions`. نص الرسالة والمرجع البنكي لا يُحفظان؛ تُحفظ بصمات بمفتاح فقط لكشف التكرار.

البنوك: `rajhi`، `alinma`، `stc`، `d360`، `barq`، `snb`.

**صيغ البنوك مبدئية.** كل أمثلة الاختبار مصطنعة، وكل بنك يبدأ `verified: False` في `app/services/bank_sms.py`. لذلك تبقى كل عملية `needs_review` حتى تعتمدها، ولا تدخل `expenses` قبل الاعتماد. لا تجعل بنكًا موثوقًا قبل اختبار رسائل حقيقية منقّحة منه.

## المسارات

| المسار | الدخول | الوظيفة |
| --- | --- | --- |
| `POST /bank-sms/token` | جلسة التطبيق | ينشئ مفتاح الاختصار ويلغي السابق. لا يظهر إلا هذه المرة |
| `DELETE /bank-sms/token` | جلسة التطبيق | يلغي المفتاح |
| `GET /bank-sms/status` | جلسة التطبيق | هل يوجد مفتاح، وآخر استخدام |
| `POST /bank-sms` | **مفتاح الاختصار** | يستقبل الرسالة. هذا المفتاح لا يفتح أي مسار آخر |
| `GET /bank-sms/transactions?status=needs_review` | جلسة التطبيق | العمليات |
| `PATCH /bank-sms/transactions/{id}/review` | جلسة التطبيق | `{"status": "confirmed"}` أو `{"status": "ignored"}`، ويقبل `category` |
| `GET /bank-sms/reports/monthly?month=2026-11` | جلسة التطبيق | المصروف والاسترداد والصافي لكل عملة |

```json
{"bank": "rajhi", "message": "نص الرسالة", "event_id": "UUID", "received_at": "2026-11-01T12:00:00+03:00"}
```

`event_id` يتولد مرة لكل رسالة ويتكرر عند إعادة المحاولة. `received_at` اختياري ويجب أن يتضمن المنطقة الزمنية.

| الرد | المعنى |
| --- | --- |
| `201` | عملية جديدة |
| `200` مع `duplicate: true` | عملية وصلت من قبل |
| `401` | المفتاح مفقود أو خاطئ |
| `409` | `event_id` لرسالة أخرى، أو مرجع بمبلغ مختلف |
| `413` / `415` | أكبر من 16 KiB / ليس `application/json` |
| `422` | حقول خاطئة أو رسالة حساسة (OTP، رقم بطاقة كامل). الرد لا يعيد نص الرسالة |
| `429` | أكثر من 120 طلبًا في الدقيقة |

## في التطبيق

- **شاشة المالية:** بطاقة "للمراجعة" تظهر عند وجود عمليات. زر اعتماد مباشر، والنقر على الصف يفتح اختيار التصنيف والتجاهل.
- **شاشة Integrations:** بطاقة "رسائل البنك" لإنشاء المفتاح واستبداله وإيقافه.

## ماذا يُحسب مصروفًا؟

- **شراء أو رسوم معتمدة:** صف في `expenses`، فتظهر في شاشة المالية واللوحة. التجاهل بعد الاعتماد يحذف هذا الصف.
- **استرداد معتمد:** يُخصم في التقرير الشهري، ولا ينشئ صف مصروف. شاشة المالية لا تخصمه بعد.
- **تحويل، سداد بطاقة، سحب نقدي:** لا تُحسب مصروفًا أبدًا، حتى لو اعتمدتها.
- **عملية مرفوضة أو فاشلة:** تُحفظ `ignored` بلا مبلغ، ولا يمكن اعتمادها.
- **رسالة مجهولة أو بأكثر من مبلغ:** `needs_review` بلا مبلغ، ولا يمكن اعتمادها.

## إعداد iPhone

أنشئ المفتاح من التطبيق: **Integrations > رسائل البنك > إنشاء مفتاح الاختصار**. يظهر مرة واحدة مع العنوان. الخطوات أدناه يدوية ولم تُجرَّب على جهاز، وأسماء القوائم تختلف حسب إصدار iOS.

**اختصار واحد باسم `Finance SMS Send`:**

1. يستقبل Dictionary، ويستخرج منه `bank` و`message`.
2. Match Text على `message`، وعند أي مطابقة Stop This Shortcut:
   ```text
   (?i)(OTP|one[ -]?time|verification|verify|authentication|passcode|password|PIN|CVV|CVC|code|كود|رمز|تحقق|تأكيد|تفعيل|توثيق|سري|كلمة.?مرور|كلمة.?المرور)
   ```
3. Match Text ثانٍ بالطريقة نفسها للأرقام الطويلة:
   ```text
   (?i)([0-9٠-٩۰-۹][0-9٠-٩۰-۹ -]{10,}[0-9٠-٩۰-۹]|SA[0-9٠-٩۰-۹ ]{20,})
   ```
4. Generate UUID، ثم Current Date بصيغة ISO 8601.
5. Get Contents of URL إلى `https://<دومين الخادم>/bank-sms`، بطريقة POST، وترويسة `Authorization` بقيمة `Bearer ` ثم المفتاح، وJSON بالحقول الأربعة.

**أتمتة لكل مرسل بنكي:**

1. من Messages سجّل اسم المرسل الفعلي. قد يكون للبنك أكثر من مرسل.
2. Automation من نوع Message مع المرسل المحدد. لا تختر كل المرسلين.
3. Dictionary فيه `bank` بقيمة البنك و`message` بنص الرسالة من Shortcut Input، ثم Run Shortcut.
4. فعّل التشغيل بلا تأكيد. دليل Apple لـiOS 27 يذكر Allow Running When Locked من Privacy في إعدادات الاختصار.

**الاختبار:** شغّل الاختصار بالنص `شراء; مبلغ: 25.50 SAR; لدى: Cafe Demo; بطاقة: *1234` وتوقع `needs_review`. ثم جرّب `OTP verification code 123456` ويجب أن يتوقف قبل الإرسال. ثم اختبر والهاتف مقفل. الرسالة تضيع إذا تعذر الاتصال وقت وصولها؛ لا توجد قائمة انتظار.

## إضافة صيغة بنك

أضف رسالة منقّحة إلى `tests/test_bank_sms_parser.py` مع النتيجة المتوقعة، ثم عدّل `app/services/bank_sms.py`. العمليات القديمة لا يُعاد تحليلها لأن نصوصها غير محفوظة.
