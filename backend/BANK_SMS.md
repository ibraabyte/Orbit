# رسائل البنك عبر اختصار iPhone

اختصار على iPhone يرسل رسالة العملية البنكية إلى `POST /bank-sms`. الخادم يقرأ منها المبلغ والعملة والمتجر وآخر 4 أرقام، ويحفظها في `bank_transactions`. نص الرسالة والمرجع البنكي لا يُحفظان؛ تُحفظ بصمات بمفتاح فقط لكشف التكرار.

البنوك: `rajhi`، `alinma`، `stc`، `d360`، `barq`، `snb`. اسم البنك **اختياري**: الاختصار الجاهز لا يرسله، فيقرأ الخادم بكلمات كل البنوك.

## ترتيب قراءة الرسالة

1. **الرسائل الحساسة** (OTP، رقم كامل، IBAN) تُرفض قبل أي خطوة (`422`).
2. **أمثلة المستخدم** (`bank_sms_templates`): لو طابقت الرسالة مثالًا واحدًا بالكامل، تُقرأ منه. الشراء والرسوم **تُحسب وحدها** (`confirmed`)، إلا لو وُجدت عملية بنفس المبلغ والعملة والبطاقة خلال 10 دقائق، فتذهب للمراجعة (`possible_duplicate`). الاسترداد وبقية الأنواع تذهب للمراجعة. لو طابق مثالان بقيم مختلفة: `template_conflict`.
3. **الذكاء الاصطناعي** (`app/services/bank_ai.py`): فقط لو ربط المستخدم مفتاحه بنفسه وترك المفتاح مفعّلًا. لا يُستخدم مفتاح الخادم أبدًا. النتيجة دائمًا للمراجعة (`read_by_ai`). مهلة 8 ثوانٍ، ثم الخطوة 4.
4. **القارئ العام** (`parse_sms`)، والنتيجة للمراجعة كما كانت.

القالب يحفظ شكل الرسالة فقط: المبلغ والعملة والمتجر وآخر 4 أرقام والمرجع تصير خانات، وكل رقم آخر "أي رقم"، والكلمات التي يختارها المستخدم (اسمه مثلًا) "أي نص". المثال وقيمه لا تُحفظ. التفاصيل في `app/services/bank_templates.py`.

**صيغ البنوك مبدئية.** كل أمثلة الاختبار مصطنعة، وكل بنك يبدأ `verified: False` في `app/services/bank_sms.py`. لذلك تبقى كل عملية `needs_review` حتى تعتمدها، ولا تدخل `expenses` قبل الاعتماد. لا تجعل بنكًا موثوقًا قبل اختبار رسائل حقيقية منقّحة منه.

## المسارات

| المسار | الدخول | الوظيفة |
| --- | --- | --- |
| `POST /bank-sms/token` | جلسة التطبيق | ينشئ مفتاح الاختصار ويلغي السابق. لا يظهر إلا هذه المرة |
| `DELETE /bank-sms/token` | جلسة التطبيق | يلغي المفتاح |
| `GET /bank-sms/status` | جلسة التطبيق | هل يوجد مفتاح، وآخر استخدام |
| `POST /bank-sms` | **مفتاح الاختصار** | يستقبل الرسالة. هذا المفتاح لا يفتح أي مسار آخر |
| `GET /bank-sms/transactions?status=needs_review` | جلسة التطبيق | العمليات |
| `PATCH /bank-sms/transactions/{id}/review` | جلسة التطبيق | `{"status": "confirmed"}` أو `{"status": "ignored"}`، ويقبل `category` |
| `GET /bank-sms/reports/monthly?month=2026-11` | جلسة التطبيق | المصروف والاسترداد والصافي لكل عملة |
| `POST /bank-sms/templates/preview` | جلسة التطبيق | `{"example"}` → ما يقرؤه القارئ العام في المثال. لا يحفظ شيئًا |
| `GET` / `POST /bank-sms/templates`، `DELETE /bank-sms/templates/{id}` | جلسة التطبيق | الأمثلة. `POST` يرد `422` بالرمز `<field>_not_in_example` لو قيمة غير موجودة في المثال كما هي |
| `GET` / `PATCH /bank-sms/settings` | جلسة التطبيق | `{"ai_read", "ai_available"}`. `404` بلا مفتاح |
| `GET /bank-sms/shortcut` | **بلا دخول** | ملف الاختصار الموقّع. لا يحتوي أي سر |

```json
{"message": "نص الرسالة"}
```

الحقول الاختيارية: `bank`، و`event_id` (يتولد مرة لكل رسالة ويتكرر عند إعادة المحاولة؛ بدونه يكشف الخادم التكرار من النص)، و`received_at` (مع المنطقة الزمنية). الاختصارات القديمة التي ترسلها كلها تبقى تعمل.

| الرد | المعنى |
| --- | --- |
| `201` | عملية جديدة |
| `200` مع `duplicate: true` | عملية وصلت من قبل |
| `401` | المفتاح مفقود أو خاطئ |
| `409` | `event_id` لرسالة أخرى، أو مرجع بمبلغ مختلف |
| `413` / `415` | أكبر من 16 KiB / ليس `application/json` |
| `422` | حقول خاطئة أو رسالة حساسة (OTP، رقم بطاقة كامل). الرد لا يعيد نص الرسالة |
| `429` | أكثر من 120 طلبًا في الدقيقة |

## في التطبيق

- **شاشة المالية:** بطاقة "للمراجعة" تظهر عند وجود عمليات. زر اعتماد مباشر، والنقر على الصف يفتح اختيار التصنيف والتجاهل.
- **شاشة رسائل البنك** (`src/app/bank-sms.tsx`، من مربع رسائل البنك في Integrations): المفتاح، وزر تثبيت الاختصار، وخطوات الأتمتة، وأمثلة الرسائل، ومفتاح الذكاء الاصطناعي.
- العملية المقروءة بالذكاء الاصطناعي عليها علامة في بطاقة المراجعة.

## ماذا يُحسب مصروفًا؟

- **شراء أو رسوم معتمدة:** صف في `expenses`، فتظهر في شاشة المالية واللوحة. التجاهل بعد الاعتماد يحذف هذا الصف.
- **استرداد معتمد:** يُخصم في التقرير الشهري، ولا ينشئ صف مصروف. شاشة المالية لا تخصمه بعد.
- **تحويل، سداد بطاقة، سحب نقدي:** لا تُحسب مصروفًا أبدًا، حتى لو اعتمدتها.
- **عملية مرفوضة أو فاشلة:** تُحفظ `ignored` بلا مبلغ، ولا يمكن اعتمادها.
- **رسالة مجهولة أو بأكثر من مبلغ:** `needs_review` بلا مبلغ، ولا يمكن اعتمادها.

## إعداد iPhone

1. في التطبيق: **رسائل البنك > أنشئ المفتاح**، ثم انسخه.
2. **ثبّت الاختصار**: يفتح `GET /bank-sms/shortcut` في تطبيق الاختصارات، ويطلب المفتاح مرة واحدة.
3. **أتمتة واحدة**: الاختصارات > الأتمتة > + > رسالة، اختر مرسلي البنوك، "تشغيل فورًا"، ثم Orbit Bank SMS.

الملف يُبنى ويُوقّع على الماك:

```bash
uv run python scripts/build_bank_shortcut.py --api https://orbit.apps.ibrabyte.app --out app/static/orbit-bank-sms.shortcut
```

**لم يُجرَّب على جوال بعد:** تثبيت الملف، وسؤال المفتاح، وتشغيله من الأتمتة، وهل تقبل أتمتة واحدة أكثر من مرسل. الرسالة تضيع لو تعذر الاتصال وقت وصولها؛ لا توجد قائمة انتظار.

## إضافة صيغة بنك

الطريقة العادية الآن: الصق رسالة مثال من شاشة رسائل البنك. للقارئ العام: أضف رسالة منقّحة إلى `tests/test_bank_sms_parser.py` مع النتيجة المتوقعة، ثم عدّل `app/services/bank_sms.py`. العمليات القديمة لا يُعاد تحليلها لأن نصوصها غير محفوظة.
