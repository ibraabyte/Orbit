# قرار: Git للمعرفة وحالة تشغيل محلية منفصلة

- الحالة: مقبول لنطاق تهيئة المستخدم لكل المشاريع.
- المعرفة المراجعة Markdown في Git. Basic Memory نسخة محلية للبحث والتحرير، وليس بديلًا وحيدًا للحقيقة.
- لكل مشروع هوية ومسار وفهرس وقاعدة مهام مستقلة، مع إعادة استخدام صورة الأدوات المثبتة. لا تتسرب ملاحظات مشروع إلى آخر.
- تبقى SQLite وDolt والمفاتيح خارج المزامنة والمستودع. ينتقل تاريخ مهام ملتزم به عبر Git، دون نسخ ملفات القواعد الحية.
- يقبل المشغّل فرع تهيئة صريحًا أثناء المراجعة فقط، ثم ينتقل للفرع المعتمد الذي يحوي علامة الهوية. يرفض المسودة المتراجعة أو غير المنشورة عند الجلب.
- التواصل والقرارات والتسليمات الجديدة بالعربي، وقواعد المنتج الأصلية باقية. هذه التهيئة لا تختار مهمة منتج أو تنشر خدمة.
- البديل المرفوض: مشاركة قاعدة حيّة أو تاريخ مهام واحد بين مستودعات مستقلة؛ كلاهما يعرّض العزل والعمل المتزامن للخطأ.

الدليل: [الربط](../integrations.md)، اختبارات المشغّل، وتسليم التهيئة بنتائجها الفعلية.
