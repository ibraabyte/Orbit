# القرار: ربط ChatGPT لكل مستخدم

التاريخ: 2026-11-02.

## السبب

طلب المستخدم تشغيل الذكاء الاصطناعي بحساب ChatGPT، مع دخول عبر المتصفح ولصق عنوان العودة في التطبيق. هذا الطلب يحدّث قرار تأجيل هذا الخيار في [قرار مفاتيح المستخدم](2026-11-02-user-ai-keys.md).

## التنفيذ

- ربط ChatGPT مستقل في جدول `chatgpt_connections`. يبدأ الطلب بحالة `pending` وينتهي بعد 10 دقائق إن لم يُستكمل.
- الخادم ينشئ PKCE و`state`، ثم يتحقق من أصل عنوان العودة ومساره، ومن تطابق `state` وصلاحيته. كل محاولة تُستخدم مرة واحدة.
- يعاد استخدام `encrypt_secret` و`decrypt_secret`. التوكنات ومعرف الحساب ووقت انتهاء الرمز داخل حزمة مشفرة واحدة لكل مستخدم. يحذف الحساب ربطه أيضًا.
- كل استدعاءات OpenAI على الخادم. الواجهة تستقبل الحالة ورابط الدخول فقط. لا تدخل بيانات ربط ChatGPT في التصدير.
- التجديد قبل الانتهاء بـ60 ثانية، وعند 401 يعاد الطلب مرة واحدة بعد التجديد. فشل المصادقة يطلب إعادة الربط. قفل الصف يحمي التجديد، وطلب قديم لا يمسح محاولة ربط جديدة معلقة.
- `ORBIT_CHATGPT_MODEL` يحدد النموذج إن ضُبط. وإلا يختار الخادم أقل `priority` من النماذج الظاهرة والمدعومة. ذاكرة الاختيار لكل مستخدم وحساب، وتُمسح عند رفض النموذج برسالة `not supported`.
- عميل Codex يقرأ SSE ويجمع النص والأدوات. الرد المنقطع لا يُحفظ كملخص ناجح.
- ربط ChatGPT المتصل له أولوية في ملخصات WHOOP. تبقى مفاتيح API الموجودة خيارًا بديلًا عندما لا يوجد ربط ChatGPT متصل. تعليمات المستخدم المحفوظة تُضاف كما في المسار السابق.

## حدود الإثبات

اختبارات الشبكة تستخدم خدمات وهمية، والترحيل يُفحص في قاعدة اختبار منفصلة. تفاصيل OAuth ونقاط Codex تتبع مواصفات المستخدم؛ [وثائق OpenAI](https://learn.chatgpt.com/docs/auth) تشرح دخول Codex بحساب ChatGPT، ولا تثبت نجاح هذه النسخة بحساب حقيقي. تجربة الحساب والنشر خطوة تالية للمستخدم.
